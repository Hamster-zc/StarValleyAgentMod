## 关键技术决策（开始前请确认）

### 1. 选什么 Embedding 模型？
- **推荐**：**`sentence-transformers/all-MiniLM-L6-v2`**
- **理由**：
  - 轻量级（约 80MB），**CPU 也能跑**，适合你的 Linux 开发机（哪怕没显卡也能用）。
  - 输出 384 维向量，FAISS 检索速度极快。
  - 不需要 GPU，安装即用。

### 2. 检索哪些内容？
- **来源**：直接检索 `conversation_turns` 表中的 `text` 字段。
- **时间范围**：初期不设时间限制（检索所有历史），后续可以限制 `game_day` 范围。

### 3. 架构位置（重要）
- **在 Host 端进行检索**（而不是 Node）。
- 流程：`ClientRequest` → **Host 检索长期记忆** → 拼接到 `prompt` → 发送给 Node。
- 这样 Node 依然无状态，只负责生成，数据库和 FAISS 索引只由 Host 维护。

### 4. 索引更新策略（Day 1 先不考虑动态更新）
- **冷启动/全量重建**：每次启动 Host 时，读取数据库所有对话，重新生成向量并构建 FAISS 索引。
- 等 Week3 后期再优化为“增量更新”。

## 今日任务（Week3 Day 1）：实现文本向量化 Pipeline

### 目标
编写一个 Python 模块，能够连接数据库，读取所有历史对话文本，调用 Sentence-Transformers 生成向量，并将向量和对应的元数据（ID、文本）保存到本地文件（`.npy` 和 `.json`），为明天构建 FAISS 索引做准备。

### 你需要新建的文件
- `rag/embedding.py`（封装 Embedding 模型）
- `rag/build_index_data.py`（或放在 `scripts/` 下，负责从 DB 读取并生成向量文件）
- 确保 `rag/__init__.py` 存在。

### 需要安装的库
```bash
pip install sentence-transformers numpy
```

### 设计指引（不提供完整代码）

1. **在 `rag/embedding.py` 中**：
   - 导入 `sentence_transformers.SentenceTransformer`
   - 定义一个类 `EmbeddingModel`：
     - `__init__(self, model_name="all-MiniLM-L6-v2")`：加载模型。
     - `encode(self, texts: List[str]) -> np.ndarray`：调用 `model.encode(texts)`，返回 numpy 数组。

2. **在 `rag/build_index_data.py`（或测试脚本）中**：
   - 导入 `shared.memory` 中的 `query_recent_turns`（或者写一个 `get_all_turns` 函数，因为没有现成的“查所有”接口，你需要写一个 SQL 查询所有对话）。
   - 从数据库读取所有 `conversation_turns`（获取 `id` 和 `text`）。
   - 过滤掉空文本。
   - 调用 `EmbeddingModel.encode()` 生成向量。
   - 使用 `np.save("storage/embeddings.npy")` 保存向量矩阵。
   - 使用 `json.dump()` 保存对应的 `ids` 和 `texts` 列表（以便后续检索时映射回文本内容）。

### 验收标准（今日）
- [ ] 运行你的脚本后，在 `storage/` 目录下生成 `embeddings.npy` 和 `metadata.json`（或 `ids.json` + `texts.json`）。
- [ ] 脚本不报错，且输出的向量维度一致（例如 `(N, 384)`）。
- [ ] 你能通过 Python 交互环境加载 `.npy` 文件并看到数组形状。

### 注意事项
- 如果数据库是空的，请先用测试脚本插入几条模拟数据（比如 Week2 的种子数据）。
- 代码中 DB 路径记得使用 `os.path.join` 绝对路径，避免 Linux/Windows 下路径问题。
- **暂时忽略增量更新**，先确保全量构建能跑通。
