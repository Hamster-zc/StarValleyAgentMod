# Week3 Day3：将 FAISS 检索集成到 Host 工作流

## 目标
- 在 Host 下发 `TaskAssignment` 前，调用 `FaissIndex.search()` 检索长期记忆。
- 将检索到的长期记忆（文本 + ID）拼接到 prompt 中，与短期记忆区分。
- 将长期记忆的 ID 也通过 `TaskAssignment` 传递给 Node，并在最终 `citations` 中体现。
- 确保短期记忆和长期记忆同时工作，不冲突。

---

## 一、架构回顾

当前 Host 的 `client_handler` 流程：

1. 收到 `ClientRequest`
2. 调用 `build_prompt_with_memory` → 读取**短期记忆**（SQLite），生成 prompt 和 `memory_ids`
3. 构造 `TaskAssignment`，发送给 Node
4. 等待 `NodeResult`，返回给 Client

Day3 的新增步骤（在步骤 2 和 3 之间）：

2.5 **调用 `FaissIndex.search()`**，检索**长期记忆**（历史对话），获取 Top-K 结果
2.6 **将长期记忆文本拼接到 prompt 中**（与短期记忆合并）
2.7 **将长期记忆的 ID 合并到 `memory_ids` 列表**（或单独字段）

## 三、具体设计指引

### 3.1 修改 `build_prompt_with_memory` 函数签名

原函数：
```python
def build_prompt_with_memory(db_path, npc_id, game_day, context, max_memory_items=6) -> Tuple[str, List[str]]:
```

增加参数：
```python
def build_prompt_with_memory(db_path, npc_id, game_day, context, 
                             max_memory_items=6, 
                             long_term_memories=None) -> Tuple[str, List[str]]:
```

- `long_term_memories`：来自 `FaissIndex.search()` 的结果列表，每个元素包含 `id`、`text`、`score`。
- 在 prompt 中增加 `Long-term Memory:` 段落，与短期记忆分开。
- 返回的 `memory_ids` 应包含**短期记忆 ID + 长期记忆 ID**（合并列表）。

### 3.2 在 Host 中初始化 `FaissIndex`

在 `host/server.py` 中，全局（或在 `client_handler` 外）初始化一次：

```python
from rag.embedding import EmbeddingModel
from rag.faiss_index import FaissIndex

embedding_model = EmbeddingModel()
faiss_index = FaissIndex(embedding_model=embedding_model)
```

### 3.3 在 `client_handler` 中调用检索

在调用 `build_prompt_with_memory` 之前，执行长期记忆检索：

```python
# 获取当前用户输入（context 最后一条）
user_input = client_msg.context[-1]["content"] if client_msg.context else ""

# 检索长期记忆
long_term_results = faiss_index.search(user_input, top_k=3)

# 传递给 build_prompt_with_memory
prompt, memory_ids = build_prompt_with_memory(
    db_path=DB_PATH,
    npc_id=client_msg.npc_id,
    game_day=client_msg.game_day,
    context=client_msg.context,
    long_term_memories=long_term_results
)
```

### 3.4 修改 `build_prompt_with_memory` 的 prompt 构建

在 `build_prompt_with_memory` 中，将长期记忆文本格式化为：

```
Long-term Memory:
- {text1} (id: {id1})
- {text2} (id: {id2})
```

然后与短期记忆、当前对话上下文拼接成最终 prompt。

同时，将长期记忆的 ID 与短期记忆 ID 合并到 `memory_ids` 列表：

```python
all_ids = memory_ids + [m["id"] for m in long_term_memories]
return full_prompt, all_ids
```

### 3.5 区分短长期记忆 ID（可选）

如果希望在 `citations` 中区分来源，可以用不同前缀：

```python
short_ids = [f"short_{id}" for id in short_term_ids]
long_ids = [f"long_{id}" for id in long_term_ids]
```

但 Day3 可以先统一合并，后续再优化。

## 四、测试验收标准

- [ ] Host 启动后，`FaissIndex` 能正常加载索引（无报错）。
- [ ] 发送一条 `ClientRequest`，Host 日志显示 `long_term_results` 非空（假设数据库有历史数据）。
- [ ] 最终 `TaskAssignment.prompt` 包含 `Long-term Memory:` 段落。
- [ ] `TaskAssignment.memory_ids` 包含长期记忆 ID。
- [ ] 最终 `NodeResult.citations` 包含长期记忆 ID（如果协议已更新）。
- [ ] 如果 `faiss.index` 或 `metadata.json` 缺失，Host 应优雅降级（返回空列表，不影响短期记忆功能）。

## 五、注意事项

- **性能**：检索应在 Host 端进行，Node 保持无状态。
- **降级**：如果 `FaissIndex.search()` 失败（如索引文件不存在），应捕获异常并返回空列表，不中断主流程。
- **Prompt 长度**：长期记忆最多取 3 条，每条文本可截断至 100 字符，避免 prompt 超长。
- **ID 传递**：确保 `TaskAssignment.memory_ids` 包含长期记忆 ID，Node 能正确回传 `citations`。
- **数据库路径**：`build_prompt_with_memory` 仍使用 SQLite 读取短期记忆，与 FAISS 独立，两者互补。
